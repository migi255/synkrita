# Connect from ChatGPT web where supported

Use an approved workspace that allows private custom MCP connections. Confirm feature access and administrator permissions in the workspace before starting. Business and Enterprise/Edu are the reference staging workspaces. Pro access may be limited to developer-mode read/fetch. Validate the three actual Synkrita tools on the selected plan. [ChatGPT workspace eligibility and permissions](https://help.openai.com/en/articles/12584461-developer-mode-and-full-mcp-connectors-in-chatgpt-beta)

1. An authorized creator opens **Plugins → + → Add custom MCP server** in the eligible web workspace and enters the exact approved HTTPS URL. Create a private development connection and select OAuth. Depending on the workspace UI, developer mode or administrator setup may be required. Copy the connection's exact callback and client identity from the management page. [Connect and test privately](https://developers.openai.com/plugins/deploy/connect-chatgpt)
2. The identity operator registers the exact callback shown for that connection. The callback can be connection-specific. The stable URL applies only where eligible, including the documented RFC 9207 requirements for new connections. Use an approved predefined registration if offered or explicitly import the published client metadata document into the provider. Pin the actual issued `client_id` claim at Synkrita. Use the precise token exchange method required by that registration. Test every requested scope and confirm a sole exact MCP audience even when OIDC scopes are present. [ChatGPT registration and OAuth](https://developers.openai.com/plugins/build/auth)
3. Install or enable the private connection for the tester. In a fresh web chat, select Synkrita with `@` and finish identity-provider sign-in. Ask it to read the supplied synthetic receipt, cite its source, trace the qualified decision and read your own synthetic investigation. The test coordinator supplies foreign and missing IDs to check withholding. Review refresh, disconnect, reconnect and suspension in the operator's separate acceptance record.

If the creation entry is missing, check plan and workspace permissions with the administrator. If login loops, check the selected callback mode, actual provider audience and scopes, refresh configuration and pinned client ID. Follow the staging matrix before publishing or admitting researchers. The selected workspace and provider must still pass that matrix.
